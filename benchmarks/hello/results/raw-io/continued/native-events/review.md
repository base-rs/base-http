# Native kqueue event-buffer review

Scope: remove the normalized event vector and conversion pass on the macOS worker-owned readiness path. The exact pre-change source and binary are frozen in before-source/ and before-server; change.diff records the two changed Rust files. Earlier local scheduler modifications are preserved and are outside this narrow review. No public interfaces or design requirements change.

Applicable requirements are scheduler context/design.md and context/io.md (private registration state, borrowed-buffer safety, event publication and retirement), plus HTTP design/implementation.md and design/duplex.md (independent progress and joined socket retirement). Protocol semantics and framing implementation remain unchanged.

Independent implementation and duplex reviewers found no blocking issue. Vec capacity covers the kernel output tail, initialized length advances only on syscall success, and failed waits retain earlier initialized events. Reallocation moves only opaque token values; controller-owned registrations do not move. Lazy decoding retains interrupt filtering, direction/error mapping, byte hints and EOF. Production dispatch, registration ownership and clear-before-reclamation ordering are unchanged. The private wait return count now reports this wait's native event count including interrupts; its production caller checks only errors.

The real UDP regression checks byte metadata, retained events after an interrupted wait, appending another wait and clearing the batch. Existing collected-pointer, callback-replacement, cross-worker closure, backpressure, urgent-data and EOF fixtures exercise the unchanged lifetime and progress boundaries. Reviews were read-only and did not independently execute tests or benchmarks.

Host validation passes 29,267/29,267 measured regions with three pre-existing unreachable exclusions; selector 184 passed/one ignored. Formatting, workspace Clippy and Rust 1.85.1 checks pass (private Bake excluded as before). Server 22 unit tests, five proxy cases and one doctest pass. A first coverage attempt encountered a stale source-map report after a comment was edited during compilation; the stable-source rerun passes. No source edits occurred during the rerun or measurement.

Both raw cohorts show roughly 5% lower median user CPU, improving four of five paired rounds each. Full HTTP has no established CPU or throughput gain. Raw throughput medians are about 1.2% lower in both cohorts with higher measured kernel time; paired throughput results are mixed, and neither a throughput gain nor neutrality is established. Host activity/core placement are uncontrolled. The simpler representation removes actual staging and one worker buffer allocation; the raw throughput limitation remains visible. Measurements and source/binary provenance are frozen beside this review. No non-macOS runtime claim is made; other backends compile the unchanged implementation.
