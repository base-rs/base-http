# Retained selector change review

Scope: ready-write early return plus direct event-pointer dispatch and deferred registration retirement, compared with the preserved notifier-only revision in results/raw-io/scheduler/final. Earlier local scheduler work is preserved; this is not a review of every pre-existing Git working-tree change. HTTP crates have no Git baseline here; their production sources remain unchanged during this continuation.

Applicable requirements: scheduler context/design.md and context/io.md; HTTP design/implementation.md (generic capabilities and ownership), design/duplex.md (independent progress, joined retirement). Existing body semantics, interim/upgrade handling and protocol framing are unaffected. No public capability or behavioral requirement was weakened.

Independent implementation and duplex reviewers inspected actual sources and new tests. No blocking lifetime, callback, native-owner, cancellation or duplex issue was found. Records are anchored before kernel add, successful deletion precedes deferred release, prior event batches are cleared before reclamation, and group close alone cannot free in-flight tokens. Failed adds/deletes quarantine state, Weak controller ownership avoids cycles, and no retained record owns native sockets or payload. Wakers/destructors execute outside locks. Linux/Android direct tokens have source-level deletion audit; other backends keep numeric routing.

Host validation: canonical all-target/all-feature coverage passes 29,264/29,264 measured regions with three pre-existing unreachable exclusions. Selector 183 passed/one ignored; workspace Clippy and Rust 1.85.1 checks pass (private Bake excluded from MSRV because its existing macro dependency needs newer syntax). HTTP semantic/body tests, 45 HTTP/1 codec cases, 22 server units, five TCP proxy cases and one server doctest pass. Benchmark MSRV/Clippy pass. Linux/Windows all-target cross-checks and Android libraries pass. Android all-target checking encounters an unrelated pre-existing process-wait test cfg error. Cross-target execution/coverage is not verified.

The raw pointer screen improves median user CPU 8.1% against an otherwise equivalent ready-write binary, in all five paired rounds. Copy-on-write routing, custom hashing, extra strong-state allocation, poll_fn reader flattening and outlined/forced-inline ready helpers are not retained. The forced remote-mutation churn check finds no observed regression at 64/512 idle registrations; it does not prove general production churn throughput.

The combined longer measurement reduces median user CPU 13.5% raw and 4.5% HTTP; Base HTTP remains 0.75% below Hyper median throughput. Final syscall diagnostics show one positive read/write per sequential request in all four modes, 41/78 bytes per positive read/write under wrk, and no write-WouldBlock calls. Fresh wall profiles put 0.6% of Native raw samples in cancellation/event/mutex work versus 0.2% for spawned Tokio. Wall samples locate code and cannot attribute on-CPU cost. Source hashes match the frozen revision and the restored release binary is byte-for-byte identical to the measured binary. Host placement/activity remain uncontrolled; system time dominates this workload, and no result is generalized to TLS, io_uring or multi-worker throughput.
