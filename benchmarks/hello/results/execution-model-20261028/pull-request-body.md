Describe Native worker/reactor execution and record the progress requirements that performance changes must preserve. The guide separates operation cost from delay between admission, preparation, issuance, completion publication and application consumption, with the existing wakeup and retirement contracts made explicit.

Apply that model to an immediate-payload-submission prototype. Five paired Hana rounds show only a 0.54% concurrent throughput change with mixed signs, while one-connection CPU/request rises 5.65% and worsens in every pair. Equal-rate tail results remain mixed. Retain the existing submission policy, the rejected prototype's measurements and patches, corrected policy comments, and a bounded-owned-read regression. Lifecycle fixtures use supported interrupted submissions to establish unissued state independently of batching policy.

Separate boundary probes include strided and pseudorandom sampling controls. They guide further research around result consumption and application batching, with explicit limits: instrumentation changes batching, and a queued read can overlap client waiting rather than contribute to response latency. Fixed offered-rate latency and unrestricted capacity remain separate cohorts; no task budget or numerical latency guarantee is introduced.
