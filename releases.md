# Releases

## Unreleased

- Fill a client request's default scheme from the `Scheme` constants instead of converting the endpoint's scheme text. This saves about 87 user instructions per response in the pooled HTTP/1 client benchmark.
- Parse HTTP/1 response heads and trailer sections with the same hand-written parser as request heads, so httparse is no longer compiled into production builds. The accepted grammar is unchanged. Chunk size lines no longer pass through a separate line-ending scan, since their grammar already rejects stray CR, LF and NUL. Rejections now report the specific defect, as request heads do: a response head reports, for example, `Invalid("invalid field name")` or `Invalid("expected CRLF")` instead of `Invalid("invalid response head")`, and an invalid trailer name is `Invalid("invalid field name")` rather than a `Body` field error. An invalid byte is reported before the section is complete, even when the section would also exceed `max_head_bytes`, and a trailer section longer than `max_head_bytes` reports `Limit("trailer section")` instead of `Limit("line length")`.
- Add `Fields::with_capacity` and `Fields::reserve`, and construct fields with less work. Field names are still checked as tokens and values are still checked for CR, LF and NUL, but both checks are now branch-free scans that the compiler vectorizes. The HTTP/1 server reserves storage for every field line of a request head with more than three, so the collection no longer grows several times while a head is read. On Linux at 64 connections, user instructions per request with 12 browser fields fall from 17,929 to 13,591, below Hyper's 15,331.
- Parse HTTP/1 server request heads with a hand-written single-pass parser instead of httparse and separate line-ending, target and field-name scans. The accepted grammar is unchanged and is documented in `design/http1-parser.md`. A request with several defects may report a different first error, and an invalid byte in the first read of a head is now reported immediately, so a connection that sends one and then closes gets `Invalid` rather than `Truncated`. On Linux at 64 connections, user instructions per request fall from 6,217 to 5,483 for a minimal request, below Hyper's 5,877, and from 22,525 to 17,929 for a request with 12 browser fields.
- Treat field values as opaque bytes in the semantic model. `Field::new` now checks only that the name is a token, so negotiated HTTP/2 and HTTP/3 extensions can carry binary values. The HTTP/1 driver enforces its own rules. It refuses to send any field value containing CR, LF or NUL, including in requests, interim responses and trailers, and reports the error before writing the head or trailer section. Other bytes pass through. `Field::has_dangerous_bytes` reports whether a value contains CR, LF or NUL. It is recorded at construction, so drivers can check it without scanning again. Received trailer values follow the RFC 9110 field-value grammar, as received head values already did. This is a breaking change: `FieldError::InvalidValue` is removed, since `Field::new` no longer rejects values.
- Represent request targets with `Scheme`, `Authority` and `Path` instead of `String`. Schemes and authorities are stored lowercase, as the canonical form of these case-insensitive components: `http` and `https` in any case are borrowed constants, other schemes are lowercased, and so are ASCII letters in authorities. Comparisons and map lookups with `str` use the lowercase text, so look up `example.com` rather than `Example.com`. The client sends a supplied authority such as `Example.COM` as `Host: example.com`, and now accepts a request scheme such as `HTTP` for a plain endpoint. Authorities and paths up to 24 bytes are stored inline, so parsing an ordinary request target needs no allocation. Each type dereferences to `str`, compares with `str` and `String`, and converts from the common string types. Code that assigns a `String` to these fields must add `.into()`, and code that reads them as `String` must use `as_str()` or `String::from`. The client's `Endpoint::authority` is now an `Authority`. On Linux at 64 connections, user instructions per request fall from 6,424 to 6,186, and storing authorities in lowercase then adds 30 to 45.
- Parse HTTP/1 server request heads with less work. The server classifies Host and hop-by-hop fields once while reading the head instead of storing and then removing them, accepts the common `reg-name[:port]` authority in a single table-driven pass, and uses cheaper character-class and CRLF checks. Accepted and rejected requests are unchanged; a request with several defects may report a different first error. On Linux at 64 connections, user instructions per request fall from 7,915 to 6,419.
