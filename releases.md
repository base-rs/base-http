# Releases

## Unreleased

- Represent request targets with `Scheme`, `Authority` and `Path` instead of `String`. Schemes and authorities are stored lowercase, as the canonical form of these case-insensitive components: `http` and `https` in any case are borrowed constants, other schemes are lowercased, and so are ASCII letters in authorities. Comparisons with `str` use the lowercase text. The client now accepts a request scheme such as `HTTP` for a plain endpoint. Authorities and paths up to 24 bytes are stored inline, so parsing an ordinary request target needs no allocation. Each type dereferences to `str`, compares with `str` and `String`, and converts from the common string types. Code that assigns a `String` to these fields must add `.into()`, and code that reads them as `String` must use `as_str()` or `String::from`. The client's `Endpoint::authority` is now an `Authority`. On Linux at 64 connections, user instructions per request fall from 6,424 to 6,186.
- Parse HTTP/1 server request heads with less work. The server classifies Host and hop-by-hop fields once while reading the head instead of storing and then removing them, accepts the common `reg-name[:port]` authority in a single table-driven pass, and uses cheaper character-class and CRLF checks. Accepted and rejected requests are unchanged; a request with several defects may report a different first error. On Linux at 64 connections, user instructions per request fall from 7,915 to 6,419.
